## TL;DR

- 这是一个“**电视剧角色 × 亲密关系原型**”的轻量测评 H5：用户完成 24 道题，得到一个匹配角色（含相似度）、雷达图、长文分析与建议，并可一键生成分享图。
- 全站采用 **token 链接访问控制**：用户需要带 `?token=xxx` 的专属链接才能进入；token 在本地持久化，且在校验通过后会从 URL 中移除，避免二次分享泄露。
- 商业化的最小闭环：**生成 token → 发给付费用户 → 用户访问并完成测评 → 到期后引导续期**。后台提供 `/admin` 页面进行 token 生成和历史管理。
- 设计目标是“**内容配置化 + 交互模板化**”，便于后续批量化生产同类测评产品（只换题库/角色/文案/主题色，复用流程和技术底座）。

## 一、产品定位与核心价值

### 1.1 产品定位

- **产品形态**：移动端优先的测评 H5（Web App），以“答题→结果分析→分享传播”为主链路。
- **内容主题（当前版本）**：测测 TA 像电视剧中的谁（聚焦恋爱/亲密关系）。
- **商业形态**：通过专属 token 链接做访问门禁（轻付费/轻会员式）。

### 1.2 核心价值

对用户（C 端）：
- 低门槛、强反馈：24 题即可获得“角色匹配 + 相似度 + 多维分析 + 建议”。
- 强情绪价值：结果页内容更像“长文解读”，支持社交分享。

对产品/运营（供给侧）：
- 可快速换皮复用：题库/角色库/文案可配置，流程可复用。
- 商业闭环清晰：token 链接可控、可设置有效期、可续期。

### 1.3 核心指标（建议）

- 首次打开 → 开始答题转化率
- 完成率（24 题）
- 结果页停留时长、分享图生成率、分享转化（被打开次数）
- 付费转化（生成 token 数 / 使用 token 数）、续期率

## 二、目标用户与使用场景

### 2.1 目标用户

- 对“影视角色 / 人格标签 / 关系解读”感兴趣的泛娱乐用户
- 希望用测评内容做社交分享的人群（朋友圈/小红书/微信群）
- 轻付费意愿用户：愿意为“更完整的结果解读/更高质量内容”付费

### 2.2 典型场景

- 朋友之间娱乐式测评：测“我/TA像谁”，分享结果图互评
- 情侣/暧昧关系中的“对照理解”：用结果做话题引子
- 内容营销：短视频/图文引流，付费解锁专属链接

## 三、核心功能模块说明

> 当前版本的页面路由：`/` 首页 → `/quiz` 答题 → `/loading` 过渡 → `/result` 结果 → `/admin` 管理后台。

### 3.1 测评流程（答题）

- **题目数量**：24 道。
- **交互**：单选题；支持上一题/下一题；最后一题点击“揭晓答案”。
- **进度提示**：顶部进度条 + 题号（第 X / 24 题）。
- **数据存储**：答题选项在会话内通过 `sessionStorage` 保存，避免刷新丢失。

用户体验关键点：
- 题面文案采用“情境 + 问题”的写法，降低理解成本。
- 选项按钮视觉上区分已选/未选，保证移动端首屏可用。

### 3.2 结果页

结果页由“强情绪价值 + 信息密度”组成：

- **主结果（英雄区）**：
  - 角色来源（哪部剧）+ 角色名
  - 相似度（MATCH xx%）
  - 角色标签、标题、金句
- **雷达图（多维度评估）**：展示关系原型的 6 个维度（例如情绪价值、责任感、边界感、稳定性、浪漫感、现实感）。
- **长文模块**：
  - 他的恋爱观（多模块卡片）
  - 你的想法（多模块卡片）
  - 相处建议（多模块卡片）

体验细节：
- 当未检测到答题记录时，会展示“默认结果示例”，并引导用户从首页重新开始。
- 主题色会随角色变化（背景渐变、按钮色、标签色、雷达图颜色），提升“结果差异感”。

### 3.3 分享（生成分享图）

- 结果页提供“**生成分享图**”按钮。
- 分享图以弹窗形式展示预览，并支持“下载图片到本地”。
- 分享图内容：品牌名、角色名、相似度、迷你雷达图、维度得分简表、恋爱观摘要。

运营侧可用玩法：
- 在分享图中固定露出品牌名/账号，引导二次传播。
- 分享图字段可做 A/B：例如把“恋爱观摘要”换成“爆点金句”。

### 3.4 token 访问控制（核心门禁）

- **全站门禁**：除 `/admin` 外，用户访问任何页面前都需要通过 token 校验。
- **token 入口**：用户从专属链接进入，例如 `/?token=xxxx`。
- **校验逻辑**：前端向 Supabase 的 `public.access_tokens` 表查询 token 是否存在且未过期。
- **隐私保护**：
  - 校验通过后，会把 token 存入浏览器 `localStorage` 以便后续访问。
  - 同时会把 URL 中的 `token` 参数移除，避免用户“复制当前地址”造成二次泄露。
- **失败分流**：无 token / 无效 token / 过期 token → 统一进入“访问受限/已过期”页面。

### 3.5 管理后台（/admin）

- **入口**：`/admin`。
- **保护方式**：管理密码（前端环境变量 `VITE_ADMIN_PASSWORD`）。
- **核心能力**：
  - 一键生成新 token（默认有效期 30 天）
  - 生成专属链接并可复制
  - 查看最近 100 条 token（含创建时间、到期时间、是否过期）

说明：当前管理后台定位为“最小可用”，方便运营快速发链接；不追求强安全。

## 四、付费/商业化设计

### 4.1 token 链接机制（售卖与交付）

- **售卖单位**：一个 token 对应一次“可访问权限”。
- **交付形态**：发给用户一条专属链接（带 `token` 参数）。
- **价值承诺**：在有效期内可反复访问并再次测评。

建议运营口径（示例）：
- “这是你的专属测评链接，有效期 30 天，随时可重新测/测别人。”

### 4.2 有效期、过期与续期流程

- **有效期**：当前后台默认 30 天（可调整策略）。
- **过期体验**：展示“链接过期，请联系进行续期”的提示文案。

续期可选流程（建议明确 SOP）：
1. 用户反馈过期 → 运营核对用户信息（付款记录/订单号/私域身份等）
2. 续期方式二选一：
   - **续期原 token**：在数据库中把该 token 的 `expires_at` 延后
   - **发新 token**：重新生成新链接并发送（更简单，也更利于风控）

### 4.3 风控与体验的平衡点

当前版本是“轻门禁、轻后台”的取舍：
- 优点：链路短、上线快、运营低成本。
- 风险：
  - token 链接可能被转发滥用
  - `/admin` 管理密码在前端打包后可被逆向（仅适合低风险/小规模场景）

规模化建议（可作为后续迭代路线）：
- token 表增加 `product_slug` / `channel` / `buyer_id` 字段，用于追踪来源与分产品隔离
- 管理后台改为“服务端生成 token”（Supabase Edge Function / 自建 API），前端不再开放 INSERT

## 五、可复用的产品设计模式（用于批量生产）

### 5.1 “内容配置化 + 交互模板化”

- **固定模板**：页面结构、交互流程、组件（进度条、雷达图、分享弹窗、卡片样式）。
- **可替换内容**：题库、角色库、结果文案、主题色、首页文案、分享图字段。

这使得新测评产品可以以“换内容”为主，而不是从 0 开发。

### 5.2 “轻付费门禁”

- 使用 token 链接作为“轻付费凭证”，不引入复杂账号体系。
- 校验通过后本地持久化 token，保证体验顺滑。
- URL 擦除 token，降低无意泄露。

### 5.3 “一键分享图”

- 把结果页的核心信息压缩成可传播的图片（适配微信/小红书）。
- 分享图采用固定版式：品牌 + 结果核心 + 雷达图 + 1 段爆点文案。

### 5.4 “最小管理后台”

- `/admin` 提供“生成链接 + 查看历史”的最小能力。
- 适合 MVP 阶段验证转化与传播，而不是长期强运营系统。

## 六、运营复用清单（更像可执行的模板）

- **上线前**：
  - 配置 Supabase 表与 RLS（确保 token 校验可用）
  - 配置 Vercel 环境变量
  - 确认默认有效期（30 天/7 天/永久）
- **日常发货**：
  - `/admin` 生成链接 → 复制 → 发给用户
- **续期/售后**：
  - 过期用户 →（续期原 token 或发新 token）→ 重新发送链接
- **活动玩法**：
  - 渠道专属 token（后续可加字段）
  - 分享图固定露出品牌 + 引导语
